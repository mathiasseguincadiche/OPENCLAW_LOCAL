# Définir les livrables

Un livrable doit décrire **ce qui doit exister**, pas seulement une activité.

## Mauvais

- « travailler sur Terraform » ;
- « améliorer la doc ».

## Bon

- module Terraform multi-fichiers avec variables, outputs et validation ;
- runbook Markdown avec prérequis, procédure, contrôles et rollback ;
- archive finale avec manifest et hashes.

## Pour chaque livrable

Préciser format, emplacement ou structure attendue, contraintes et critère d'acceptation. Cela permet au planificateur de créer des tâches réellement vérifiables.
