# Ingénieur Release / Forges

## Quand l'utiliser

Git, branches, commits, PR/MR, checks, version, changelog, package, release et vérification distante.

## À lui fournir

Dépôt cible, état Git, politique de branche, livrables validés, version visée et règles de publication.

## Ce qu'il doit produire

Plan de publication, package/hashes, état des checks, preuves distantes et statut de release.

## Règle importante

Publication distante, merge ou release doivent respecter les gates humains et les politiques du projet. Un artefact local validé n'est pas automatiquement « publié ».
